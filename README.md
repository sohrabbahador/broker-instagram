# سرویس هوشمند اینستاگرام — بروکر املاک (@broker_amlak.ir)

سرویسی مستقل (FastAPI) که به همان MongoDB مشترک ربات‌های بله (`broker_database.files`) وصل می‌شود، فایل‌های «موجود» را می‌خواند و از طریق **Instagram API with Instagram Login** (بدون Facebook Login و بدون Facebook Page) منتشر می‌کند، به کامنت/دایرکت پاسخ می‌دهد، سرنخ ثبت می‌کند و گزارش می‌دهد.

## معماری
```
ربات بله فروش ─┐                      ┌─► انتشار (تک‌عکس/کاروسل)
ربات بله اجاره ─┼─► MongoDB files ─► سرویس اینستاگرام ─┼─► پاسخ کامنت/دایرکت + سرنخ ─► هشدار به مدیر در بله
               │   (is_available)     (این پروژه)      └─► آمار ۷ روزه + گزارش هفتگی
```
| ماژول | وظیفه |
|---|---|
| `tokens.py` | ورود OAuth، توکن ۶۰‌روزه‌ی رمزنگاری‌شده، تمدید خودکار |
| `ig_client.py` | انتشار، کامنت، دایرکت، آمار (میزبان `graph.instagram.com`) |
| `media.py` | لینک لحظه‌ای: عکس هنگام درخواست متا از بله دانلود و ۴:۵ می‌شود؛ هیچ عکسی ذخیره نمی‌شود |
| `content.py` | کپشن، هشتگ، حذف شماره/مالک/آدرس دقیق، دسته‌بندی پیام |
| `publisher.py` | صف، تناوب فروش/اجاره، اسلات‌های زمانی، تأیید مدیر، تلاش مجدد |
| `inbox.py` | وب‌هوک کامنت/دایرکت، پاسخ خودکار، ثبت سرنخ، ارجاع به انسان |
| `insights.py` | جمع‌آوری آمار، گزارش هفتگی |

## راه‌اندازی (به ترتیب)
1. **ساخت اپ متا**: در developers.facebook.com اپ بسازید، محصول *Instagram* را اضافه کنید و در بخش *API setup with Instagram login* مقدار `Instagram App ID` و `Instagram App Secret` را بردارید. (برای *ساخت اپ* حساب Meta Developer لازم است؛ اما کاربر نهایی/پیج شما هیچ‌جا Facebook Login یا Page ندارد.)
2. حساب `broker_amlak.ir` باید **Professional (Business/Creator)** باشد. آن را به‌عنوان *Instagram Tester* یا نقش اپ اضافه و دعوت را از داخل اینستاگرام تأیید کنید. برای حساب خودتان با دسترسی Standard نیازی به App Review نیست.
3. در Render یک Web Service جدید بسازید، متغیرهای `.env.example` را وارد کنید (همان `MONGODB_URI` ربات‌ها).
4. در اپ متا: Redirect URI = `IG_REDIRECT_URI`، وب‌هوک = `PUBLIC_BASE_URL/webhook` با `IG_WEBHOOK_VERIFY_TOKEN`؛ فیلدهای `comments` و `messages` را Subscribe کنید.
5. مرورگر: `PUBLIC_BASE_URL/ig/login?secret=OAUTH_ADMIN_SECRET` ← ورود با اینستاگرام ← پیام «حساب متصل شد».
6. با `PUBLISH_MODE=approval` شروع کنید؛ پیش‌نویس‌ها در بله به مدیر می‌رسد (لینک تأیید/رد).

## مسیر پیشنهادی ارتقا به اتوماسیون
| فاز | حالت | شرط عبور |
|---|---|---|
| ۱ (۲ هفته) | `approval` + پاسخ‌ها خودکار | ≥ ۹۵٪ پیش‌نویس‌ها بدون ویرایش تأیید شود |
| ۲ | `PUBLISH_MODE=auto` | هیچ خطای محتوایی (قیمت/اطلاعات غلط) در ۲ هفته |
| ۳ | افزودن ریل/استوری (نیاز به ویدیو) و A/B تست هوک | داده‌ی آمار کافی |

## محدودیت‌های واقعی (صادقانه)
- **«۹۹٪ خودکار» برای انتشار، پاسخ‌های ساده، سرنخ‌گیری و گزارش** واقع‌بینانه است. اما قیمت نهایی/مذاکره، آدرس دقیق، هماهنگی بازدید و بستن قرارداد عمداً به انسان ارجاع می‌شود؛ اشتباه در این موارد هم اعتبار برند و هم ریسک حقوقی دارد.
- دایرکت: پاسخ فقط در **پنجره‌ی ۲۴ ساعته** پس از پیام کاربر مجاز است و ارسال انبوه/تبلیغاتی به افرادی که پیام نداده‌اند ممنوع است؛ سیستم هم سقف پاسخ روزانه به هر کاربر دارد.
- سقف انتشار: متا ۵۰ پست در ۲۴ ساعت اجازه می‌دهد؛ این سرویس پیش‌فرض ۳ پست در روز می‌گذارد (کیفیت > حجم).
- **حذف پست از طریق API ممکن نیست.** وقتی ملکی ناموجود می‌شود، پست قبلی باقی می‌ماند؛ برای همین قبل از انتشار دوباره موجود بودن بررسی می‌شود و بهتر است در پست‌ها عبارت «برای موجودی به‌روز، دایرکت بدهید» بماند.
- Reels/Stories و پست ویدیویی در این نسخه نیست (نیاز به ویدیو دارد؛ `rupload` در فاز ۳).
- عکس‌ها باید JPEG با نسبت ۴:۵ تا ۱٫۹:۱ باشند؛ `media.py` خودکار اصلاح می‌کند.
- ثبت نام مشتری و شماره‌ی او فقط برای پیگیری همین درخواست ذخیره می‌شود؛ سیاست حریم خصوصی در بیو/لینک پیج توصیه می‌شود.
- من در محیط ساخت به اینترنت دسترسی نداشتم: منطق کپشن/پاک‌سازی/دسته‌بندی و پردازش تصویر تست شد (`python -m unittest discover -s tests`)، اما **اتصال زنده به متا و بله تست نشده**. در فاز ۱ با یک پست آزمایشی راستی‌آزمایی کنید؛ نام متریک‌های آمار و نسخه‌ی API (`IG_API_VERSION`) را با مستندات متا هم‌خوان نگه دارید.

## یافته‌ی امنیتی در ربات فروش (core.py)
تابع `_public_ai_text` برای حذف شماره‌ها **کار نمی‌کند**: الگوها داخل رشته‌ی raw با دو بک‌اسلش (`\\d`, `\\s`) نوشته شده‌اند و جداکننده‌ی خطوط هم `"\\n"` (متن لفظی) است. نتیجه: شماره‌ی تلفن داخل متن فایل می‌تواند به Gemini برسد و خروجی یک خط می‌شود. اصلاح:
```python
line = re.sub(r"(?<!\d)(?:\+?98|0)?9\d{9}(?!\d)", "[شماره حذف شد]", line)
line = re.sub(r"(?<!\d)0\d{10}(?!\d)", "[شماره حذف شد]", line)
return "\n".join(lines).strip()
...
return "\n".join(chunks)[:14000]      # و بقیه‌ی "\\n" ها در get_ai_sale_inventory_context
```
همچنین `bot.py` ربات رهن داخل zip ربات فروش هم کپی شده است؛ حذفش کنید تا اشتباهاً دیپلوی نشود. شناسه‌های واقعی چت در `.env.example` هر دو پروژه هست؛ بهتر است با مقدار فرضی جایگزین شوند.


## فایل‌های مخزن و استقرار اولیه
- فایل `.env.example` فقط نمونه است؛ مقادیر واقعی را در GitHub قرار ندهید.
- در Render متغیرهای الزامی `MONGODB_URI`، `TOKEN_ENC_KEY` و `OAUTH_ADMIN_SECRET` را قبل از اولین راه‌اندازی تنظیم کنید.
- کلید Fernet را با `python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"` تولید کنید. برای `OAUTH_ADMIN_SECRET` از `python -c "import secrets; print(secrets.token_urlsafe(48))"` استفاده کنید. خروجی‌ها فقط در Render ذخیره شوند.
- این نسخه هنوز بدون اعتبارنامه Meta قابل اتصال یا انتشار نیست؛ تا تکمیل تنظیمات Meta، انتشار واقعی فعال نخواهد شد.
- فایل ZIP را استخراج و تمام محتویات پوشه (از جمله `render.yaml` و `.env.example`) را در ریشه‌ی مخزن خصوصی GitHub بارگذاری کنید؛ خود ZIP را در مخزن بارگذاری نکنید.
